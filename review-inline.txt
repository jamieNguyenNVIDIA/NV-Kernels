The change
==========

Inside arm_smmu_def_domain_type, replaces:

    if (pdev->vendor == PCI_VENDOR_ID_NVIDIA &&
        (pdev->device == 0x2E12 || pdev->device == 0x2E2A ||
         pdev->device == 0x2E2B))
            return IOMMU_DOMAIN_DMA;

with:

    if (pdev->vendor == PCI_VENDOR_ID_NVIDIA &&
        pdev->device >= 0x2E00 && pdev->device <= 0x2E3F)
            return IOMMU_DOMAIN_DMA;


Range correctness
=================

All three originally listed IDs (0x2E12, 0x2E2A, 0x2E2B) fall inside
[0x2E00, 0x2E3F] — no behavioral change for currently-shipping silicon.


Collision check
===============

Searched the kernel tree for any other NVIDIA device ID references in
0x2E00–0x2E3F:

  - The only kernel-side reference to PCI_VENDOR_ID_NVIDIA combined
    with IDs in this range is this SMMU quirk itself.
  - Other vendors (Intel AGP, OMAP, IMX) do define IDs in the same
    numeric range, but the quirk is gated by
    vendor == PCI_VENDOR_ID_NVIDIA (0x10de) and won't match them.

So no current NVIDIA device gets pulled into the DMA-domain quirk
unintentionally; the 64-ID expansion only affects future DGX Spark
iGPU SKUs that NVIDIA owns.


Reachability
============

arm_smmu_def_domain_type is wired into arm_smmu_ops.def_domain_type,
called by the IOMMU core for every PCI device on an ARM SMMUv3 system
at probe. No NULL-deref surface (pdev is always non-NULL after the
dev_is_pci(dev) gate).
