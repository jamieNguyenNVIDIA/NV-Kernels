Top commit (SIS_UTIL)
=====================

The new SIS_UTIL block in select_idle_capacity() mirrors select_idle_cpu():
nr = READ_ONCE(sd->shared->nr_idle_scan) + 1, early "return -1" for an
overloaded LLC (nr==1), and an in-loop early exit gated by
!prefers_idle_core so the bound only applies when not chasing fully-idle
cores. The exit predicate

    best_fits == ASYM_IDLE_CORE_UCLAMP_MISFIT (-4)

is the lowest best_fits value that can be stored in the loop, since
fully-fitting cores return immediately via "if (fits > 0 && preferred_core)
return cpu;" — nothing better is achievable later in the scan.


Concerns investigated and dismissed
===================================

1) nr_busy_cpus tracking on asym systems. Commit 1 makes
set_cpu_sd_state_busy / set_cpu_sd_state_idle skip the atomic_inc /
atomic_dec when sd->shared is NULL (asym claimed the shared object).
That does leave nr_busy_cpus on the asym shared object stale, but
nohz_balancer_kick() short-circuits to "goto unlock" on asym systems
before reading nr_busy_cpus:

    sd = rcu_dereference(per_cpu(sd_asym_cpucapacity, cpu));
    if (sd) {
        if (check_misfit_status(rq)) { ... }
        /* Skip the LLC logic [...] */
        goto unlock;
    }

So the stale counter is never consumed. The defensive NULL check only
matters on the NUMA-overlapping-asym fallback where LLC owns the shared
and the counter is maintained normally.

2) Enum value collision. ASYM_IDLE_CORE_BIAS = -3 and
ASYM_IDLE_CORE_COMPLETE_MISFIT = -3 share a value. This is intentional —
the bias is applied via "fits += ASYM_IDLE_CORE_BIAS", and the post-bias
mapping leaves preferred-core misfits comparable against thread-level
fits. The "best_fits > ASYM_IDLE_CORE_BIAS" check at the tail of the
function uses the bias as the documented threshold for "no preferred-core
candidate found", which is consistent.

3) Unbounded scan when prefers_idle_core is true. By design — the
commit comment ("nr only limits the scan when not preferring an idle
core") matches the implementation. Same shape as select_idle_cpu()'s
has_idle_core path.


6.17-specific note
==================

The PR description states upstream PATCH 1/6 (the rcu_dereference_all()
switch) was deliberately skipped because 71fedc41c23b is not in the
6.17 base. Confirmed — 71fedc41c23b is not an ancestor of
24.04_linux-nvidia-6.17-next. The 6.17 select_idle_sibling already
uses plain rcu_dereference(), and the wakeup paths reaching this code
hold rcu_read_lock(), so the new sd->shared dereference in
select_idle_capacity() is RCU-safe.
