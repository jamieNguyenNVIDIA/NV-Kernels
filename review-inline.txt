Top commit (32dd95c9f8ed)
=========================

REACHABILITY: confirmed. fwctl_init is the module init function for
drivers/fwctl/main.c, run at boot.

The change:

  -module_init(fwctl_init);
  +subsys_initcall(fwctl_init);

This moves fwctl's class registration earlier in the boot sequence
(subsys initcall, level 4) so it runs before regular module_init
(level 6).

The commit message identifies the NULL-deref scenario correctly:

  - CXL is linked before fwctl in drivers/Makefile, so
    cxl_pci_driver_init() runs before fwctl_init().
  - cxl_pci_probe() calls fwctl_register() + device_add(). With
    fwctl_class not yet registered, class_to_subsys() returns NULL
    and knode_class is skipped.
  - On device removal, class_to_subsys() now returns non-NULL (init
    has run), so device_del() calls klist_del() on the uninitialized
    knode -> NULL deref.

Moving fwctl to subsys_initcall registers the class before CXL probes
devices, eliminating the window. Fixes: 858ce2f56b52 ("cxl: Add FWCTL
support to CXL"). Reviewed-by Dave Jiang and Kai-Heng Feng. Merged
upstream as a55f80233f38 and into v7.1.
